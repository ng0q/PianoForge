# Objective

Сравнить предобученные модели автоматической транскрипции сольного фортепиано на одинаковых записях MAESTRO v3 и на собственном аудио с MIDI-эталоном. Оценить качество, скорость и расход памяти, чтобы выбрать модели для следующего этапа разработки PianoForge.

# Candidates

| Модель | Роль в исследовании |
| - | - |
| hFT-Transformer (Sony) | Компактный кандидат с выходами frame, onset, offset и velocity. |
| Transkun V2 | Кандидат, который оценивает интервалы нот целиком. |
| SFT-CRNN | Модель с CQT-признаками и чекпойнтом с Optimal Transport Loss. Выходы onset и offset, без обучаемой головы velocity. |
| HRT (Kong et al.) | Транскрипция нот и педали сустейна с высоким временным разрешением. |
| Onsets and Frames (Magenta) | Исторический baseline, включённый в конфигурацию запуска. |
| YourMT3 | Рассмотрена при разборе архитектур. Для сольного фортепиано отложена из-за дополнительной сложности токенного декодирования и извлечения уверенности для верификатора. |

Список моделей первого запуска зафиксирован в ноутбуке. [Ноутбук бенчмарка](../audio-transcription/notebooks/01_amt_benchmark.ipynb)

# Methodology

- **MAESTRO v3.0.0.** Десять полных записей из test split, по одной на композицию, около 66,3 минуты суммарно. Выборка зафиксирована с seed `20261123` и одинакова для всех моделей.

- **Psycho.** Две дорожки по 75,746 с одного исполнения вальса с длительным сустейном, обновляемым примерно раз в такт. iPad на пюпитре записывал в моно, iPhone на столе примерно в двух метрах — в стерео. Обе дорожки записаны в 48 кГц и выровнены с одним MIDI на 878 нот.

- **Оборудование и ПО.** Apple Silicon, macOS, PyTorch MPS, float32. В результатах указаны Python 3.12.14, PyTorch 2.15.0, mir_eval 0.8.2 и pretty_midi 0.2.11.post0. Точная модель чипа и объём установленной памяти в артефактах прогона не указаны.

- **Метрики.** Onset требует совпадения высоты в пределах 50 центов и начала в пределах 50 мс. Onset+offset дополнительно проверяет конец ноты с допуском max(50 мс, 20% эталонной длительности). Эталонное окончание берётся из MIDI note-off. CC64 сохраняется в MIDI, но при расчёте длительности эталонных нот не применяется. Precision, Recall и F1 усреднены по успешно обработанным файлам.

- **Скорость и ресурсы.** Задержка после прогрева включает чтение аудио, предобработку, инференс и декодирование. Загрузка модели и подсчёт метрик находятся вне замера. RTF равен суммарной задержке, делённой на длительность успешно обработанного аудио. В MAESTRO учитывались пиковый RSS процесса и, где доступно, максимум по замерам выделенной памяти MPS. Замеры MPS после обработки файлов Psycho не отражают пик.

# Observations

- **Качество и скорость.** Transkun V2 лидирует по обеим F1 среди моделей, прошедших десять записей MAESTRO. На Psycho SFT-CRNN получила лучший Onset F1 на обеих дорожках. Её медианная задержка — 32.07 с против 7.76 с у hFT и 6.58 с у Transkun.

- **Условия записи.** На дорожке с iPhone у всех моделей выше Onset F1. Recall hFT вырос с 0.604 до 0.854. На этой же дорожке Transkun нашёл 94,4% эталонных атак, а hFT получил более высокий Precision — 96,4% против 81,7%. Устройства, расположение и число каналов различались одновременно.

- **Сустейн.** В Psycho Onset+Offset F1 лежит в диапазоне 0.004–0.055. В MIDI у 876 из 878 нот клавиша отпущена при нажатой педали. Например, у C♯5 атака на 4,7805 с, отпускание клавиши на 4,940 с, педали — на 5,805 с. При прогнозе конца на отпускании педали ошибка offset составит 865 мс при допустимых 50 мс. В диалоге выделили две проверки — влияние определения offset и остаточную рассинхронизацию. Разрыв между двумя F1 на MAESTRO также требует проверки.

- **Ранние домашние пробы hFT.** Отмечены пропуски низкого баса и снижение качества на громких плотных аккордах двух рук. Быстрые арпеджио распознавались лучше. Эти наблюдения задают материал для отдельных диагностических тестов.

# Limitations

- В MAESTRO всего десять композиций. SFT-CRNN завершила четыре файла, на остальных возникли зависания MPS или нехватка памяти. 8,94 ГиБ — значение из лога одного аварийного запуска. Сопоставимый пик для SFT-CRNN не измерен. Magenta не запустилась под Python 3.12, чекпойнт Onsets and Frames отсутствовал локально.

- Psycho — одно исполнение с почти постоянной педалью. Две дорожки позволяют сравнить условия записи этого дубля. Для выводов об устройствах, расстоянии и разных инструментах нужны дополнительные записи. Остаточный сдвиг и дрейф синхронизации не измерены.

- Эксперимент оценивает предобученный инференс на одном окружении. Стоимость дообучения, точность педали и velocity, квантование и читаемость итоговой партитуры ещё не измерены.

# Decision

| Модель | Предварительная роль | Основание |
| - | - | - |
| Transkun V2 | Основной кандидат | Лучший результат среди завершивших прогон на десяти MAESTRO-записях, минимальная задержка на обоих наборах и высокий Recall на iPhone. |
| hFT-Transformer | Основной кандидат | Самая компактная модель, быстрая на обеих выборках, высокая точность атак на iPhone. Раздельные выходы подходят для прототипа адаптера уверенности. |
| SFT-CRNN | Сравнительный baseline | Лучший Onset F1 на обеих дорожках Psycho и близкие к Transkun результаты на четырёх общих MAESTRO-файлах. Более высокая задержка и неполный прогон MPS снижают приоритет интеграции. |
| HRT | Исключить из активного отбора | Более тяжёлый чекпойнт, более долгий инференс и уступающие Transkun обе F1 на MAESTRO и обе Onset F1 на Psycho. |
| Onsets and Frames | Отложить | Сравнимых результатов запуска нет. |

В обсуждении 25 ноября Илья предложил оставить hFT и Transkun и оценить стоимость их дообучения. Выбор одной модели для интеграции остаётся открытым.

# Next Steps

1. **Проверить offset и синхронизацию.** Пересчитать существующие предсказания с двумя эталонами — MIDI note-off и длительностью, продлённой по CC64 с учётом повторов той же ноты. Продление по CC64 даёт приближение времени звучания. Записать тот же фрагмент без педали, проверить совмещение MIDI и аудио в начале и конце дубля и посмотреть распределения ошибок onset и offset.

2. **Расширить домашний тест.** Добавить примеры низкого баса, плотных аккордов, быстрых арпеджио и повторов. Для адаптации к домашним записям сохранить фиксированный MAESTRO holdout, чтобы отследить изменение качества на чистом звуке.

3. **Оценить дообучение hFT и Transkun.** Замерить время шага, пропускную способность, рабочий batch size и пик памяти на целевом оборудовании.

4. **Проверить идею общего верификатора.** Сделать модельный адаптер, который связывает декодированные ноты с исходной уверенностью модели. Сравнить исправления на одних и тех же ошибках. Проверять ритмическое квантование и MusicXML на следующем этапе обработки.
